# LabPulse Architecture Decision Records

Architecture Decision Records document significant technical and product decisions.

## Naming

Use:

```text
ADR-001-short-decision-name.md
ADR-002-short-decision-name.md
```

**Exception:** [ADR-000: Architectural Philosophy](ADR-000-architectural-philosophy.md) is intentionally numbered 000 so it sorts first in any file listing. It is the first document every contributor — human or AI — should read before any other ADR.

## Required Sections

Each ADR should include:

- Title
- Status
- Date
- Context
- Options considered
- Decision
- Reasons
- Risks
- Consequences
- Conditions for revisiting

## Status Values

- Proposed
- Accepted
- Superseded
- Deprecated
- Rejected

## Rules

- Do not rewrite accepted ADR history.
- Create a new ADR when a decision changes.
- Link superseded ADRs.
- Keep decisions concise.
- Record tradeoffs honestly.
